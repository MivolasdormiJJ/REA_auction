# REA Auction — платформа обратных аукционов

Учебный полнофункциональный веб-проект для публикации студенческих задач и выбора исполнителя через открытые обратные аукционы по правилу второй цены.

- **Сайт с Django API:** https://rea-auction.onrender.com/
- **Статическая учебная демонстрация:** https://mivolasdormijj.github.io/REA_auction/
- **Ветка публикации:** `main` — Render автоматически развёртывает коммиты этой ветки.

## Технологии

Backend: Python 3.12, Django 5.2, Django REST Framework, PostgreSQL, Gunicorn, WhiteNoise. Frontend: React, TypeScript, Vite, Ant Design, Axios. Развёртывание: Docker и Render; CI — GitHub Actions. Статическая учебная страница дополнительно публикуется через GitHub Pages.

## Возможности

Регистрация без подтверждения email, вход через Django sessions/CSRF, каталог с 24 категориями по направлениям подготовки, создание задач и модерация, открытые ставки, выбор победителя и цены по правилу второго минимума, уведомления о результатах, административная панель и примеры учебных аукционов.

## Запуск и тесты

```bash
# Установить Python-зависимости и подготовить базу
pip install -r requirements.txt
python manage.py migrate
python manage.py test auction

# Разработка интерфейса
cd frontend
npm ci
npm run dev
npm run build
```

Для локального запуска с PostgreSQL предусмотрен `compose.yaml` и шаблон `.env.example`. Vite проксирует `/api` на `http://localhost:8000`. В production многоступенчатый `Dockerfile` собирает React, затем запускает Django через Gunicorn; PostgreSQL подключается через `DATABASE_URL`.

Команда `python manage.py close_auctions --loop` закрывает просроченные торги и определяет результат. Коммиты в `main` проверяются GitHub Actions и автоматически развёртываются Render.

## Статистика и аналитика

- В профиле (`/profile`) видны собственные ставки, победы, процент побед, созданные аукционы и подтверждённые выполненные задания.
- **Победа не считается выполнением работы.** После закрытия аукциона победитель берёт заказ в работу и отправляет результат, а заказчик принимает его или запрашивает доработку. При приёмке сохраняется `TaskCompletion`.
- В админ-панели (`/admin`) доступны KPI платформы, разбивка по статусам и категориям, месячная динамика и CSV-экспорт аукционов, пользователей и ставок. Все административные отчёты защищены проверкой Django-суперпользователя.
- CSV-отчёты содержат сведения текущей базы; примерные данные помечаются `[ДЕМО]`. Суммы итоговых цен не являются фактическими платежами.

## Выполнение заказа и приёмка работы

Победитель закрытого аукциона может начать выполнение заказа и отправить текстовый результат. Заказчик проверяет отправленную версию и принимает её либо возвращает на доработку с причиной. Новые версии и решения сохраняются в PostgreSQL (`WorkOrder`, `WorkSubmission`); работу невозможно принять без сдачи результата. История доступна только заказчику, победителю и администратору через API.
