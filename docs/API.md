# REA Auction — действующий API

API обслуживается Django REST Framework по пути `/api/`. Формат обмена — JSON. Даты — ISO 8601, суммы — целое число копеек. Актуально для ветки `main`.

## Авторизация

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/auth/csrf/` | Получить CSRF-токен |
| POST | `/api/auth/register/` | Регистрация по логину, email и паролю **без подтверждения email** |
| POST | `/api/auth/login/` | Авторизация по логину и паролю |
| GET | `/api/auth/me/` | Текущий пользователь и роли `can_moderate`, `is_admin` |
| POST | `/api/auth/logout/` | Завершить сессию |

Сессии Django хранятся на сервере; браузер передаёт cookie и заголовок `X-CSRFToken` при изменении данных. В production фронтенд и API работают на одном домене. Регистрация требует пароль не менее 12 символов; введённый email сохраняется без проверки владения почтовым ящиком. Legacy endpoint `/api/auth/verify-email/` оставлен для совместимости, но при новой регистрации не нужен.

## Категории и аукционы

Все следующие URL начинаются с `/api/`.

| Метод и путь | Назначение |
|---|---|
| `GET categories/` | Категории обучения с пагинацией |
| `GET auctions/` | Список задач с пагинацией и фильтрами |
| `POST auctions/` | Создать собственный черновик |
| `GET auctions/{id}/` | Открыть карточку доступной задачи |
| `PATCH auctions/{id}/` | Изменить собственный черновик / отклонённую задачу |
| `POST auctions/{id}/submit/` | Отправить на модерацию |
| `POST auctions/{id}/approve/` | Модератор одобряет задачу |
| `POST auctions/{id}/reject/` | Модератор отклоняет задачу |
| `POST /api/auctions/{id}/review/` | Заказчик публикует оценку 1–5 и комментарий после приёмки работы |
| `GET /api/performers/{user_id}/reputation/` | Профиль исполнителя, агрегированный рейтинг и последние отзывы |
| `GET /api/auctions/{id}/chat/?after={message_id}` | Приватная история и новые сообщения заказчика и победителя |
| `POST /api/auctions/{id}/chat/` | Отправка неизменяемого сообщения с обязательным `Idempotency-Key` |
| `GET auctions/{id}/bids/` | Список **всех открытых ставок** в доступном аукционе |
| `POST auctions/{id}/bids/` | Подать одну неизменяемую ставку |

Фильтры `GET auctions/`: `status`, `category`, `search`, `page`, `mine=1`. По умолчанию размер страницы — 20. Поиск, статусы и категории комбинируются. Список доступен авторизованным пользователям; черновики других заказчиков скрыты, суперпользователь видит все статусы.

Создание требует заголовок `Idempotency-Key`. Пример тела:

```json
{
  "category": 1,
  "title": "Разработка лендинга",
  "description": "Создать адаптивный сайт по техническому заданию.",
  "budget_kopecks": 150000,
  "ends_at": "2027-01-10T12:00:00Z",
  "due_at": "2027-01-20T12:00:00Z"
}
```

Пример ставки:

```http
POST /api/auctions/1/bids/
Idempotency-Key: 0f0bf93e-1821-4cf3-9c5c-f644d957ce69
X-CSRFToken: <полученный токен>
Content-Type: application/json

{"amount_kopecks":70000}
```

Сервер не разрешает заказчику ставить на собственную задачу, превышать бюджет, менять отправленную ставку и ставить после закрытия. Точный повтор с тем же ключом и телом возвращает существующую запись. **Открытые ставки** содержат `bidder_id`, `bidder_username`, `amount_kopecks`, `created_at`.

## Завершение торгов

Состояния: `draft → review → open → closed`, с ответвлениями `rejected`, `paused`. Закрытие производит фоновая команда `python manage.py close_auctions --loop` через `auction/services.py`. Побеждает минимальная ставка, при равенстве — самая ранняя. При двух и более ставках итоговая цена — **вторая минимальная**, при одной — бюджет заказчика. До закрытия `winner_id` и `payment_kopecks` не раскрываются.

## Уведомления и администрирование

| Метод и путь | Назначение |
|---|---|
| `GET /api/notifications/` | Победа, проигрыш и закрытие собственной задачи |
| `GET /api/admin/users/` | Все пользователи — только Django-суперпользователь |
| `GET /api/admin/auctions/` | Все аукционы — только Django-суперпользователь |
| `/django-admin/` | Встроенная административная панель Django |

Уведомления вычисляются из завершённых аукционов; отдельной таблицы уведомлений и статусов прочтения нет. Записи ставок, результаты и права защищаются на сервере, а не только скрытием кнопок на фронтенде.

## Ошибки и особенности

- `400` — ошибки ввода данных, включая отсутствие ключа идемпотентности.
- `403` — отсутствие сессии, прав, CSRF или запрет участия заказчика.
- `404` — объект отсутствует или скрыт от пользователя.
- `409` — конфликт состояния, повторная ставка или несовместимый идемпотентный повтор.
- `405` — неподдерживаемый метод.

Тесты находятся в `auction/tests.py`, `auction/test_registration.py`, `auction/test_admin_access.py`, `auction/test_notifications.py` и `auction/test_student_catalog.py`. CI запускает `python manage.py test auction` на PostgreSQL и `npm run build` для React.

## Выполнение заказа и приёмка

После закрытия аукциона с победителем начинается отдельный процесс выполнения. Статус самих торгов при этом не меняется.

| Метод | URL | Роль |
|---|---|---|
| GET | `/api/auctions/{id}/work/` | Заказчик и победитель: состояние и история версий |
| POST | `/api/auctions/{id}/work/start/` | Победитель: начать работу |
| POST | `/api/auctions/{id}/work/submit/` | Победитель: отправить результат |
| POST | `/api/auctions/{id}/work/request-revision/` | Заказчик: запросить доработку |
| POST | `/api/auctions/{id}/work/accept/` | Заказчик: принять работу |
| POST | `/api/auctions/{id}/complete-work/` | Совместимый путь приёмки, требует отправленной работы |

Статусы: `not_started → in_progress → submitted → accepted`, либо `submitted → revision_requested → submitted`.
Результат передаётся в JSON `{"result_text":"Описание результата от 20 до 10000 символов"}` с обязательным заголовком `Idempotency-Key`. С тем же ключом и результатом повтор безопасен; изменённый текст с прежним ключом даёт 409. Запрос на доработку: `{"feedback":"Замечания длиной от 5 до 2000 символов"}`. Все версии сохраняются. При приёмке создаётся `TaskCompletion`, который увеличивает статистику выполненных работ ровно один раз. Загрузка файлов пока не реализована.
