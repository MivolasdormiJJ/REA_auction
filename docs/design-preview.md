# REA Auction — светлый SaaS дизайн-макет

Запуск: `cd frontend && npm ci && npm run dev`. Откройте `http://localhost:5173/design-preview`.

## Объяснение для обычного пользователя

**Заказчик** размещает задачу, максимальный бюджет и срок торгов. После проверки модератором исполнители могут участвовать.

**Исполнитель** выбирает подходящую задачу и отправляет одну открытую ставку — цену, за которую готов выполнить работу. Изменить ставку после отправки нельзя, цены других участников доступны для просмотра.

**Победитель** — участник с самой низкой допустимой ставкой. При равенстве выигрывает более ранняя ставка (дополнительный tie-breaker — ID записи).

**Итоговая цена** при двух и более ставках равна второй самой низкой ставке. При одной ставке — максимальному бюджету заказчика. В UI обязательно объяснять это правило **до** отправки ставки.

Пример с бюджетом 10 000 ₽: А предлагает 7 000 ₽, Б — 8 500 ₽, В — 9 500 ₽. А побеждает, итоговая сумма — 8 500 ₽. Это *не аукцион на повышение* и не обычная покупка по предложенной цене.

**Приватность:** лестница в макете — учебная. Настоящий API отображает ставки и имена участников; после закрытия раскрывает победителя и итоговую сумму.

## Изоляция и интеграция

Маршрут `/design-preview` является открытой демонстрационной страницей, в которой отсутствуют реальные запросы создания заказов или ставок. Используются локальные `useState` и демонстрационные суммы. Работающие страницы и Django API не заменены.

Нажатия «Добавить мою ставку», «Завершить пример» и «Сначала» изменяют только иллюстрацию. На следующем этапе согласованный дизайн можно интегрировать с `getAuctions`, `getAuction` и `placeBid`, сохраняя правило приватности.

Все стили ограничены корнем `.rea-design`. В коде есть комментарии `ПРОБЛЕМА`/`РЕШЕНИЕ`.
